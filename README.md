# formatfast

Локальный CLI на Go для форматирования JSON/JSONL и чтения многострочных логов.
Без сторонних зависимостей, сети, браузера, сервера и телеметрии.

Реализован сценарий из Format Express: читабельный JSON с отступами и извлечение
строкового поля `message` с настоящими переносами и табуляцией. Это самостоятельная
реализация, не копия закрытого движка сайта. XML, HTML, SQL, YAML, HJSON и восстановление
произвольно повреждённых логов в эту версию не входят.

## Быстрый старт

Команда называется `formatfast`, GitHub-репозиторий — `leadfact/format-fast`.
Собрать локальный бинарник и запустить из каталога проекта:

```sh
make build
./bin/formatfast '{"log.level":"debug","message":"hello\nworld"}'
./bin/formatfast /path/to/log.json
./bin/formatfast -extract message /path/to/log.json
```

Сборка для своей системы (Go 1.23+):

```sh
go build -trimpath -o bin/formatfast ./cmd/formatfast
go test ./...
```

Можно работать без установки в PATH. Чтобы получить короткую команду в текущем
терминале, находясь в каталоге проекта:

```sh
export PATH="$PWD/bin:$PATH"
```

## Установка через Homebrew

Формула живёт в отдельном репозитории
[leadfact/homebrew-format-fast](https://github.com/leadfact/homebrew-format-fast).
Homebrew подключает его автоматически при установке; отдельный `brew tap` не нужен.
Установка стабильного релиза:

```sh
brew install leadfact/format-fast/formatfast
formatfast --version
formatfast '{"message":"hello\nworld"}' --extract message
```

Подготовка релиза, обновление формулы и переход со старого tap описаны в
[docs/HOMEBREW.md](docs/HOMEBREW.md). Формула устанавливает готовый бинарник
для macOS/Linux на arm64/amd64 с проверкой SHA-256; Go для установки не нужен.

## Использование

Три способа ввода: текст одним аргументом, файл, stdin. Флаги могут стоять **до или
после ввода**. Поддерживаются `-flag` и `--flag`.

```sh
formatfast '{"log.level":"debug","message":"hello\nworld"}'
formatfast log.json
cat log.json | formatfast
tail -f app.jsonl | formatfast --stream
```

Аргумент, похожий на JSON (объект, массив, строка, число, `true`, `false`, `null`),
считается текстом; остальные — путём к файлу. При отсутствии аргумента или аргументе
`-` читается stdin. Некорректный JSON вроде `{bad}` выдаёт ошибку разбора.
Явно выбрать источник можно через `--text '…'` или `--file path` — одновременно
задавать несколько источников нельзя. Для имён, похожих на JSON, используй `--file`.
Перед именем с начальным дефисом можно поставить `--` либо передать его в `--file`.

JSON следует заключать в одинарные shell-кавычки: `'{"x":1}'`. Кавычки нужны
оболочке, чтобы она не изменила текст **до запуска команды**. Строки вроде `\n`
и `\t` внутри этих кавычек передаются без изменений. Если в самом JSON встречается
апостроф, его можно записать как `\u0027`. Очень большие данные удобнее передавать
через stdin/файл из-за системного ограничения размера аргументов процесса.

```sh
# Форматировать JSON; по умолчанию 2 пробела.
cat /path/to/log.json | formatfast
formatfast -indent 4 /path/to/log.json

# Аналог кнопки раскрытия message на сайте.
formatfast -extract message /path/to/log.json
formatfast '{"message":"HEADERS:\n\tAccept: application/json"}' --extract message

# Явно выбрать текст или файл, когда автоматическое определение не подходит.
formatfast --text '{"x":1}'
formatfast --file /path/to/log.json

# JSON Pointer: вложенное поле, массив, ключ с точкой.
formatfast -extract /events/0/message /path/to/log.json
formatfast -extract log.level /path/to/log.json

# Строка с JSON внутри: извлечь и отформатировать вторым вызовом.
formatfast -extract payload /path/to/log.json | formatfast

# Оставить извлечённую строку в JSON-кавычках.
formatfast -extract message -json /path/to/log.json

# Снять ровно один слой экранирования отдельной JSON-строки.
formatfast '"HEADERS:\n\tAccept: application/json"' --unescape

# Компактный JSON без потери токенов. Для JSONL использовать оба флага.
formatfast -compact /path/to/log.json
formatfast -stream -compact /path/to/app.jsonl

# Непрерывный поток JSONL: результат выдаётся после каждой строки.
tail -f /path/to/app.jsonl | formatfast -stream -extract message

# Подсветка в терминале: auto / always / never.
formatfast -color always /path/to/log.json | less -R

# Запись через временный файл и атомарную замену результата.
formatfast -output /path/to/pretty.json /path/to/log.json

# Ограниченный JSON-like режим; нестандартная запись сохраняется.
formatfast "{level:'debug', amount:1.2300,}" --loose
```

Обычный режим принимает один JSON или несколько документов, разделённых пробельными
символами, включая JSONL. `-stream` ожидает один полный документ на физической строке;
многострочный pretty JSON следует читать без этого флага. Пустые строки потока пропускаются.

`-extract message` ищет буквальный ключ верхнего уровня. Для вложенных ключей используется
JSON Pointer: `/events/0/message`. В сегменте указателя `~1` означает `/`, `~0` означает `~`.
Пустой указатель (`-extract ''`) выбирает документ целиком. Возвращаются все совпадения:
повторяющиеся ключи и документы JSONL не теряются. Отсутствие совпадения — ошибка.

Извлечённые строки печатаются как текст; объекты, массивы, числа и литералы форматируются.
Каждый результат заканчивается переводом строки: существующий завершающий `\n` не
дублируется. Начальные и внутренние пустые строки сохраняются. Это текстовый CLI,
а не средство побайтовой выгрузки строк без завершающего newline.

`-unescape` принимает строку в JSON-кавычках, не произвольный текст. Декодируется один слой:
`"a\nb"` становится двумя строками, а `"a\\nb"` — текстом `a\nb`. Windows-пути
`"C:\\new\\test.txt"` не превращаются в переносы и табы. Unicode и суррогатные пары
декодируются стандартным `encoding/json`; одиночные суррогаты заменяются на U+FFFD.
Раскрытый текст выводится как есть, включая управляющие символы; JSON-представление
можно получить через `-extract … -json`.

## Сохранность данных

- Форматтер не преобразует JSON в `map` или `float64`.
- Порядок и повторяющиеся ключи сохраняются.
- Числа `9007199254740993`, `1.2300`, `-0`, `1E+09` остаются в исходной записи.
- Escape-последовательности внутри JSON-строк при форматировании сохраняются.
- В строгом режиме некорректная грамматика — ошибка с позицией, без попытки починки.
- Вход должен быть UTF-8; начальный UTF-8 BOM допускается и убирается.
- `-loose` разрешает комментарии `//` и `/* */`, одинарные кавычки,
  ключи без кавычек из ASCII-букв/цифр и `_$.-@`, завершающие запятые.
  Результат этого режима может не быть валидным JSON: нестандартная запись сохраняется.
- Префиксы наподобие `2026-10-04 DEBUG {...}` автоматически не удаляются.

Обычный режим сначала проверяет весь ввод, затем пишет результат. При ошибке разбора
частичный результат не выдаётся. `-stream` проверяет каждую строку отдельно: если позже
встретится ошибка, ранее выданные строки уже останутся в stdout. С `-output` файл
заменяется только после успешной обработки всего ввода; до замены оригинал сохраняется.
Не перенаправляйте вывод shell через `> input.json` в тот же входной файл — для этого
используйте `-output input.json input.json`.

Лимиты: по умолчанию 64 МиБ входа и 512 уровней вложенности; настраиваются
`-max-bytes` и `-max-depth`. В потоковом режиме лимит размера применяется к одной
физической строке, включая её перевод строки. Память в обычном режиме пропорциональна
входу и результату; отступы глубоко вложенных документов увеличивают размер результата.
В потоковом режиме память зависит от размера одной строки, а не всего файла.

Коды выхода: `0` — успех/справка, `1` — ошибка обработки или I/O, `2` — ошибка разбора
флагов. Сообщения идут в stderr; данные — в stdout. Цвет автоматически выключается
при перенаправлении, `NO_COLOR` или `TERM=dumb`. Извлечённый текст не раскрашивается.

## Архитектура и подключение интерфейса

```text
cmd/formatfast/main.go       точка входа
internal/cli/cli.go           аргументы, stdin/файлы, поток, атомарная запись
internal/cli/input.go         выбор текста/файла/stdin, порядок флагов
formatter/formatter.go       публичный API и типы
formatter/parser.go          грамматика, структура, вывод и выбор значений
formatter/scanner.go         сканирование строк и чисел без конвертации
formatter/string.go          декодирование строк
formatter/pointer.go         разбор JSON Pointer
```

Пакет `formatter` не обращается к терминалу, файлам, сети или глобальным настройкам.
Позже его можно вызвать из HTTP-обработчика, desktop-приложения или Go/WASM-адаптера;
CLI при этом не потребуется переписывать. Никаких серверов сейчас не запускается.

```go
pretty, err := formatter.Format(input, formatter.Options{Indent: 2})

// При повторных вызовах можно переиспользовать выделенную память.
buffer, err = formatter.AppendFormat(buffer[:0], input, formatter.Options{})

values, err := formatter.Extract(input, "/events/0/message", formatter.Options{})
// Проверить err и len(values) перед обращением к values[0].
text, err := formatter.DecodeString(values[0].Raw, false)
```

`Extract` возвращает срезы исходного буфера без копирования. Не изменяйте вход, пока
пользуетесь результатом. `AppendFormat` требует непересекающиеся входной и выходной
буферы. Вызовы с независимыми буферами можно выполнять параллельно.

## Проверки и производительность

```sh
go test ./...
go test -race ./...
go test ./formatter -fuzz FuzzFormat -fuzztime 15s -parallel 2
go test ./formatter -run '^$' -bench . -benchmem
```

Тесты сравнивают результат со стандартным `json.Indent`, проверяют сохранение токенов,
большие числа, повторяющиеся ключи, вложенные указатели, Unicode, пути, ошибки,
потоковые строки длиннее 64 КиБ и сохранение выходного файла при ошибке.
Fuzz-тест сравнивает компактные токены валидного JSON до и после форматирования.

Результаты конкретного замера приведены в `BENCHMARKS.md`. Бенчмарки измеряют пакет
в памяти; запуск процесса, чтение диска, раскраска и отрисовка терминала в них не входят.
